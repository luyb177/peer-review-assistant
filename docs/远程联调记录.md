## 1. 远程 MySQL

- 服务器：用户授权的 `lty-server-1`。
- 复用已有 MySQL 容器，仅操作专用库 `peer_review_assistant`；未改容器配置、重启服务或修改其他业务库。
- 操作前目标库已存在，字符集 utf8mb4，表数量为 0。
- 使用管理员身份建立 10 张 InnoDB 表：
  - users、courses、assignments、criteria、submissions；
  - review_tasks、reviews、review_scores、ai_advice、operation_logs。
- 新建运行账号 `peer_review`，随机口令仅写入本地配置。
- 仅授予该专用库的 SELECT、INSERT、UPDATE、DELETE；没有全局管理、CREATE、DROP 或 GRANT OPTION 权限。
- 账号要求 SSL，来源限制为初始化时本机的公网出口 IP，而不是开放 `%`。
- 从受信任的 SSH 连接取得 MySQL 公开 CA 证书，未读取或复制私钥。
- Java 连接采用 PKCS12 信任库和 `VERIFY_CA`。当前 MySQL 自动生成的服务器证书不匹配公网 IP，因此不伪称已完成主机名校验，也不关闭 CA 校验或改动其他项目的服务器证书。
- 实测协商密码套件：TLS_AES_128_GCM_SHA256。

**换网络、切换 VPN 或公网出口 IP 改变时，账号可能被拒绝连接，需要通过管理员重新配置允许的来源；不要为省事直接改成 root 或全网开放。**

## 3. JDBC 性能问题与修复

最初使用 Connector/J 8.4.0 时，真实探针耗时明显偏长。线程栈确认停在：

```text
InetAddress.getHostName
ConnectionImpl.<init>
DriverManager.getConnection
```

旧驱动为连接遥测属性直接计算反向 DNS，即使没有启用遥测也可能等待。将官方 Connector/J 更新为 26.7.0；该版本通过 Supplier 延迟取得地址属性，避免无用解析。

同一环境实测：

- 初次连接从约 5.35 秒降至约 0.59 秒。
- 更新后的整套远程探针约 5.84 秒，包含 JVM 源码启动、登录、权限/TLS 检查、中文 CRUD、回滚及状态读取。

这是本机这次测量，不承诺所有网络具有相同耗时。

源码依据：

- https://github.com/mysql/mysql-connector-j/blob/8.4.0/src/main/user-impl/java/com/mysql/cj/jdbc/ConnectionImpl.java
- https://github.com/mysql/mysql-connector-j/blob/26.7.0/src/main/user-impl/java/com/mysql/cj/jdbc/ConnectionImpl.java

## 4. 本地 AI 网关

- 已使用本地私有配置访问模型列表，配置的模型可用。
- 使用 Anthropic 官方 Java SDK，经本机回环 HTTP 网关完成一次最小 Messages 请求。
- 请求仅为连通性提示，不含教师、学生、作业正文或数据库信息；max_tokens=128，关闭自动重试。
- 返回文本 `OK`，stop_reason 为 end_turn。
- 验证后在本地配置启用 AI。
- HTTP 仅允许精确的 localhost、127.0.0.1、::1；外部地址仍必须 HTTPS。
- `ai.refusalFallback=auto`：官方地址启用服务端专用回退，兼容网关默认不附加该参数。

此处验证的是接口和模型连通性，不是实际作业评审质量；尚未把真实学生作业发送给模型。
