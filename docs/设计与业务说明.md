# 设计与业务说明

## 1. 范围

单机 Java 桌面客户端连接远程 MySQL，支持教师发布作业、学生提交、随机互评、人工评分、AI 参考意见和统计。不是多人实时在线服务器，不包含选课系统或自动判分。1.1.0 已实现教师资料和学生文档附件，详见完整课程设计报告第 5.3 节。

## 2. 模块与边界

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| domain | 不可变实体、集合防御性复制、状态枚举 | JDBC、Swing 控件 |
| service | 权限、时间规则、流程、事务、输入校验 | 窗口布局、模型 HTTP 格式 |
| scoring | 规则校验、归一化加权策略 | 数据访问 |
| allocation | 洗牌错位分配及名单边界校验 | 持久化任务 |
| dao | 连接作用域、PreparedStatement、关系映射 | GUI 提示 |
| ai | 参考意见契约、提示词、SDK 调用 | 填写人工分数 |
| ui | 事件、表格、角色工作台、SwingWorker；LoginPanel 静态视图与 LoginFrame 业务绑定分离 | 拼接业务 SQL；设计期连接外部服务 |
| config/util | 本地配置、CSV、密码、通用筛选 | 决定业务状态 |

## 3. 状态与时间

```text
SUBMISSION --教师在时间窗口内成功分配--> REVIEWING --教师结束--> CLOSED
```

- 创建后立即开放提交；互评开始时间即提交截止时间。
- 时间到达不会擅自创建任务，仍需教师显式触发。
- 分配失败事务回滚，保留 SUBMISSION；不会留下部分任务。
- 每个任务只能保留一条当前人工评分；PENDING 提交后变为 COMPLETED，不能重复新增。
- COMPLETED 在互评时间内允许本人显式修改，版本递增；或撤回删除评分与明细，恢复 PENDING 后重新提交。
- 修改/撤回要求评分记录 ID 与版本均匹配，防止旧窗口覆盖或撤回重新提交的新记录。教师、已截止或已结束记录只读。
- 截止前结束要求所有任务完成，截止后允许保留未完成任务。
- 已有提交后冻结作业与规则，防止修改分母、权重或删除历史证据。

## 4. 评分公式

每项得分 `s_i`，区间 `[min_i,max_i]`，百分比权重 `w_i`：

```text
总分 = Σ ((s_i - min_i) / (max_i - min_i)) × w_i
Σ w_i = 100
```

使用 BigDecimal 和 DECIMAL128 中间精度，最终 HALF_UP 保留两位小数。输入至多两位小数，禁止缺项、多项、重复编号、越界、零宽区间和非法权重。

例如完整性权重 60、区间 0—100、得分 80；规范性权重 40、区间 10—20、得分 15，则总分为 `0.8×60 + 0.5×40 = 68.00`。

统计以每份提交已完成互评的总加权分为样本，分别计算 AVG/MAX/MIN。无评分时统计值为空，并显示已完成/分配人数；未完成任务不当作零分。

## 5. 分配算法

仅已提交学生参与，每人只有一个提交。先洗牌，再把序列中第 i 份提交交给第 i+1 至 i+N 位学生（下标循环）。

由 `1 ≤ N < M` 可直接证明：

- 不会自评；
- 同一提交的评审人不重复；
- 每份恰有 N 名评审人；
- 每名学生恰有 N 条待评任务；
- 时间复杂度 O(M×N)，无随机重试死循环。

这是「随机洗牌后的循环错位」，不是从全部可能分配方案中等概率采样；对课程作业的随机、均衡约束足够，若研究统计公平性应进一步评估不同算法。

## 6. 数据库结构

产品建表脚本是 `src/main/resources/schema.sql`，SchemaManager 直接读取它形成检查规范，不另维护一份独立 DDL。用户可先由管理员建立专用库；若所填账号具有对应 CREATE 权限，切换时也可自动创建缺失专用库和表。应用不创建数据库用户或给自己授权，结构冲突不删除重建。

| 表 | 主要字段与约束 |
|---|---|
| users | 用户名唯一、显示名、PBKDF2 哈希、教师/学生角色 |
| courses | 课程名、说明、所属教师 |
| assignments | 所属课程、标题、说明、互评起止、盲评、阶段 |
| criteria | 所属作业、维度名、权重、区间；同作业维度名唯一 |
| submissions | 所属作业、学生、正文、时间；作业+学生唯一 |
| review_tasks | 提交、评审人、状态；提交+评审人唯一 |
| reviews | 任务、version（默认 1，修改递增）、总分、人工评语、时间；任务唯一 |
| review_scores | 互评记录+评分项复合主键、各项得分 |
| ai_advice | 任务主键、参考文本、请求模型名、生成时间 |
| operation_logs | 操作人、动作、非敏感摘要、时间 |
| attachments | 作业、可空提交、文件名/类型/大小/SHA-256、原始字节、提取文本/状态、上传人/时间 |

外键保护关系完整性，任务唯一约束及互评记录唯一约束作为防重复的第二道保护。课程删除要求无作业；作业删除要求无提交，只有评分项随其无业务数据的作业级联删除。

## 7. 并发和异常

- 每次写入独立事务、独立连接，隔离级别 READ_COMMITTED。
- 对作业及其下属提交/任务，先锁作业行再重新读取关联状态。
- READ_COMMITTED 保证等待锁后的查询看到其他事务刚提交的任务状态；否则 MySQL 默认 REPEATABLE_READ 的旧快照可能误导校验。
- 随机分配、人工评分、修改和撤回均为原子事务，评分明细、任务状态和审计任一步失败均回滚。
- 修改以记录 ID + version 匹配更新并递增版本；撤回按外键顺序删除评分明细/主记录并恢复任务。重新提交获得新记录 ID，旧版本为 1 的窗口也无法操作新记录。
- 统计直接聚合当前评分，不缓存均值。撤回后立即排除该分数，最后一份评分撤回则均值/极值为空，分配人数不变；AI 参考意见不随人工撤回删除。
- 连接使用 try-with-resources；事务回滚失败保留为 suppressed cause。
- 界面只展示不含凭据和原始响应体的错误信息，网络请求放到 SwingWorker。
- 单次人工点击发起一次 AI 请求，不自动重试付费调用。

## 8. 安全与隐私边界

- 用户密码使用随机盐 PBKDF2WithHmacSHA256，不存明文；本地配置中的数据库密码/API Key 仍是明文，应限制文件权限。
- SQL 值由 PreparedStatement 绑定，不接受来自界面的 SQL 片段。
- 学生访问任务时校验评审人，教师访问作业时校验课程所有者。
- 盲评在服务层返回任务前替换作者字段；没有自动消除正文中的身份线索。
- 模型只拿到正文与规则，不拿用户/作者字段；正文仍属外发数据，每次请求需确认。
- AI 返回纯文本，不作为 HTML 展示，也不解析为自动评分。
- RE2/J 正则避免指数回溯；CSV 对公式前缀转义，避免在表格软件中执行公式。
- 这是教学用直连数据库桌面架构；真实部署若客户端和服务器互不信任，应增加服务端身份和权限边界，不能把持有数据库凭据的桌面客户端视为强安全隔离。

## 9. 复用

自制组件：`Database/Jdbc`、`Passwords`、`CsvExporter`、`TableFilter`、`AppConfig`、`ConfigProfiles`、`SchemaManager`、`AiServices` 和 `Ui.work`。配置切换采用隔离草稿，测试/表结构准备成功后原子保存；MySQL 切换销毁旧登录，避免跨库复用用户 ID。

第三方库：MySQL Connector/J（JDBC 驱动）、FlatLaf（Swing 外观）、RE2/J（正则）、Anthropic Java SDK、Jackson（JSON）、JUnit（测试）；OpenAI 兼容适配使用 JDK HttpClient + Jackson。H2 只在测试作用域，不是运行时数据库替代。

这些库由应用主动调用；JUnit 作为测试框架反向调用测试方法。当前没有为了体现「框架」而引入 Spring 等额外基础设施。
